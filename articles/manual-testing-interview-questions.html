Most fresher interviews for QA, manual testing and software tester roles follow the same pattern: basics first, then test cases and bugs, then process, then one or two “how would you test this?” scenarios. The answers below are short on purpose. Say the one-line answer, then add an example. Examples are what make an interviewer remember you.

Testing basics

1. What is software testing?
Checking a product to find differences between what it should do (expected) and what it actually does (actual), so problems are found before users find them.

2. Why is testing needed?
Because people make mistakes. Testing finds them early, when they are cheap to fix, and protects users, money and the company’s name.

3. What is the difference between error, defect, bug and failure?
An error is a human mistake. It leaves a defect in the product, which we usually call a bug. When the defect shows up in real use, it is a failure. Full explanation with an example.

4. What is the difference between verification and validation?
Verification asks “are we building the product right?” (reviews of documents, designs and code, without running it). Validation asks “are we building the right product?” (running the software and checking it meets user needs).

5. What is the difference between QA and QC?
Quality assurance improves the process so defects are prevented. Quality control checks the product to find defects. Testing is part of QC.

6. What are the seven principles of testing?
Testing shows the presence of defects, not their absence; exhaustive testing is impossible; test early; defects cluster together; the pesticide paradox (the same tests stop finding new bugs); testing depends on context; and absence of errors is a fallacy (a bug-free product can still be useless).

7. What is the difference between manual and automation testing?
Manual testing is done by a person following steps and using judgement. Automation uses scripts to repeat checks quickly. Manual is better for exploratory, usability and new features; automation for regression and repeated checks.

Types and levels of testing

8. What are the levels of testing?
Unit testing (single function, by developers), integration testing (modules working together), system testing (the whole product) and acceptance testing (by the client or users, also called UAT).

9. What is the difference between functional and non-functional testing?
Functional testing checks what the system does (login, payment, search). Non-functional testing checks how well it does it (speed, security, usability, compatibility).

10. What is black box, white box and grey box testing?
Black box: test without seeing the code. White box: test with knowledge of the code, such as paths and conditions. Grey box: some knowledge, for example checking the database or API while testing the screen.

11. What is the difference between smoke and sanity testing?
Smoke testing is a quick, broad check that a new build is stable enough to test at all. Sanity testing is a quick, narrow check that a specific fix or feature works before deeper testing.

12. What is regression testing?
Re-testing existing features after a change, to make sure the change did not break something that used to work.

13. What is the difference between retesting and regression testing?
Retesting checks that a specific bug is fixed, using the same steps. Regression checks that the fix did not break anything else.

14. What is exploratory testing?
Learning, designing and running tests at the same time, without written test cases, guided by curiosity and experience. It finds bugs that scripted tests miss.

15. What is ad hoc testing?
Informal testing without any plan or documentation, often trying random inputs to break the product.

Test cases and test design

16. What is a test case? What fields does it have?
Steps, data and an expected result that check one thing. Fields: ID, title, preconditions, test data, steps, expected result, actual result, status, priority. How to write a test case.

17. What is the difference between a test case and a test scenario?
A scenario is what to test in one line. A test case is exactly how, with steps and an expected result.

18. What is boundary value analysis?
Testing at the edges of allowed ranges, because that is where bugs hide. For an age field of 18 to 60, test 17, 18, 60 and 61.

19. What is equivalence partitioning?
Dividing inputs into groups that should behave the same and testing one value from each group, to cut the number of tests without losing coverage.

20. What is a traceability matrix (RTM)?
A table that maps each requirement to its test cases, so you can prove every requirement was tested.

21. Write test cases for a login page.
Name the groups first: positive, negative, security, UI and performance. Then give examples from each. 40 login page test cases.

Bugs and bug reports

22. What does a good bug report contain?
Title, environment, preconditions, steps to reproduce, expected result, actual result, severity, priority, evidence and notes. Example and template.

23. What is the difference between severity and priority?
Severity is how bad the bug is; the tester sets it. Priority is how soon to fix it; the product owner sets it. Examples of all four combinations.

24. Give an example of low severity, high priority.
A spelling mistake on the main sign-in button. It harms nothing, but every visitor sees it.

25. Give an example of high severity, low priority.
A crash in an old app version almost nobody uses, or in a feature that is not released yet.

26. Explain the bug life cycle.
New, Assigned, Open, Fixed, Retest, Verified, Closed, with side paths Rejected, Duplicate, Deferred and Reopened. Every status explained.

27. What do you do if a developer says “it is not a bug”?
Check the requirement again, reproduce it, add evidence, and if you still disagree, ask the product owner to decide. Stay polite and factual.

28. What do you do if a bug cannot be reproduced?
Note the exact environment, data and time, check the logs, record a video, and try other devices or accounts. Log it with everything you know and mark how often it happens.

SDLC, STLC and Agile

29. What is the STLC?
Software testing life cycle: requirement analysis, test planning, test case design, test environment setup, test execution and test closure.

30. What is the difference between SDLC and STLC?
SDLC covers building the whole product, from requirements to maintenance. STLC is the testing part inside it.

31. What is a test plan?
A document that says what will be tested, how, by whom, on which environments, with what entry and exit criteria, risks and schedule.

32. What is the role of a tester in Agile?
Testers join from the start of each sprint: they review user stories, help write acceptance criteria, test as features are built and keep regression running. Testing is not a separate phase at the end.

33. What are entry and exit criteria?
Entry criteria must be met before testing starts (for example, build deployed and smoke test passed). Exit criteria say when testing can stop (for example, all high-priority cases run and no open critical bugs).

Scenario questions

34. How would you test a pen / a lift / a water bottle?
This checks how you think, not your knowledge of pens. Ask questions first (who uses it, what is it for), then list functional, non-functional, negative and safety checks. Structure beats a long list.

35. How would you test a shopping cart?
Start with the maths: add the totals yourself, check discounts, tax and delivery. Then quantities (0, negative, very large), stock limits, coupons that expired, prices changing between cart and checkout, and what happens if the payment fails.

Frequently asked questions

What questions are asked in a manual testing interview for freshers?

Mostly basics (what is testing, error vs bug vs failure, verification vs validation), types of testing (smoke, sanity, regression), test cases and test design, bug reports, severity vs priority, the bug life cycle, STLC and one or two scenario questions such as testing a login page.

How do I prepare for a manual testing interview?

Learn short answers to the common questions, practise writing test cases and bug reports for real apps, prepare two or three examples of bugs you found, and practise thinking out loud on scenario questions.

Is manual testing a good career for freshers in India?

Yes, it is a common entry point into IT. Many testers later move into automation, API testing, performance testing or QA lead roles, so learning one automation tool alongside manual testing helps.

What is the most important skill for a manual tester?

Attention to detail combined with clear writing: noticing that something is wrong, and describing it so precisely that a developer can reproduce it from the report alone.
