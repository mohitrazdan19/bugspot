Job keeps retrying past its limit: “Attempt 7 of 3”

P2 · MajorBeginnerJobs

Want to find it yourself first? This page gives away the answer. Play this bug on a fake app screen and see if you can spot it in three tries.

Spot this bug

The clue

Check the numbers next to each job.

Steps to reproduce

  1. Make the warehouse API fail
  2. Watch the “Sync stock” job in the job runner

Expected result

The job stops after 3 attempts and is marked Failed

Actual result

It is on attempt 7 of 3 and still retrying

Why it matters

This is a major (P2) bug. The feature still works in part, but users get wrong information or a broken step, and many will notice. It should be fixed before or soon after release.

Testing tip

Test what happens when a dependency is down. Endless retries pile up load and hide the real failure.

How to find bugs like this

Backend bugs hide behind a screen that looks fine: jobs that run twice, retries that never stop, stale caches, reports that say success when nothing happened. When you test, try these checks:

  • Check that each action happens exactly once.
  • Look at logs, outboxes and job history, not just the screen.
  • Test what happens on a slow network, a retry and a double click.
  • Compare cached values with the source of truth.
