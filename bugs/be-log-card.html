Backend testing · Logs

Full card number and CVV are written to the server logs

P1 · CriticalIntermediateLogs

Want to find it yourself first? This page gives away the answer. Play this bug on a fake app screen and see if you can spot it in three tries.

Spot this bug

The clue

Logs should never hold something a thief would want.

Steps to reproduce

  1. Pay for an order with a card
  2. Open the payments-service logs

Expected result

Card masked, like card=••••1111, and no CVV at all

Actual result

card=4111111111111111 cvv=123 exp=09/28

Why it matters

This is a critical (P1) bug. It can lose money, expose private data or stop people from finishing a key task. A bug like this should block a release and be fixed straight away.

Testing tip

Search logs for test card numbers, passwords and tokens after every payment or sign-in test. Debug logging is a common leak.

How to find bugs like this

Backend bugs hide behind a screen that looks fine: jobs that run twice, retries that never stop, stale caches, reports that say success when nothing happened. When you test, try these checks:

  • Check that each action happens exactly once.
  • Look at logs, outboxes and job history, not just the screen.
  • Test what happens on a slow network, a retry and a double click.
  • Compare cached values with the source of truth.
