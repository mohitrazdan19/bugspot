API testing · Orders API

Order paid in rupees is returned with currency “USD”

P2 · MajorBeginnerOrders API

Want to find it yourself first? This page gives away the answer. Play this bug on a fake app screen and see if you can spot it in three tries.

Spot this bug

The clue

This is an Indian store. Check every field.

Steps to reproduce

  1. Place a ₹1,499 order on the India store
  2. Send GET /api/orders/1204

Expected result

"currency": "INR"

Actual result

"currency": "USD", so 1499 could be shown or refunded as $1,499

Why it matters

This is a major (P2) bug. The feature still works in part, but users get wrong information or a broken step, and many will notice. It should be fixed before or soon after release.

Testing tip

An amount without the right currency is a wrong amount. Check currency on every money field.

How to find bugs like this

API bugs live in the JSON between the app and the server: wrong records returned, fields that leak private data, bad status codes and limits that are not enforced. When you test, try these checks:

  • Read the whole response body, not only the status code.
  • Ask for other users’ records on purpose.
  • Look for fields that should never leave the server.
  • Send values at and past every limit.
