A successful sign-in is logged as ERROR

P4 · CosmeticBeginnerLogs

Spot this bug

The clue

Does each label match what happened?

Steps to reproduce

  1. Sign in with the right details
  2. Read the auth-service logs

Expected result

INFO user signed in successfully

Actual result

ERROR user signed in successfully

Why it matters

This is a cosmetic (P4) bug. It is a small visual or wording problem. It is cheap to fix and worth reporting, because many small slips add up to a product that feels unfinished.

Testing tip

Wrong log levels flood alerts and hide real errors. Check that the level matches the event when you read logs.

How to find bugs like this

Backend bugs hide behind a screen that looks fine: jobs that run twice, retries that never stop, stale caches, reports that say success when nothing happened. When you test, try these checks:

  • Check that each action happens exactly once.
  • Look at logs, outboxes and job history, not just the screen.
  • Test what happens on a slow network, a retry and a double click.
  • Compare cached values with the source of truth.
